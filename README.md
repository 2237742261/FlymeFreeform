魅族 Flyme 的小窗，将“呼之即来，挥之即去”做得轻巧又顺手。几次简单的滑动与轻点，便能处理眼前的小事，这份细腻的巧思让人愉悦。

本项目通过 Xposed 模块，将这份即用即走的快捷交互带到 ColorOS。

## 功能

- **角落轮盘**：从左右下角斜向内上滑呼出扇形菜单，滑选应用后松手以小窗打开。
  轮盘大小（70%–115%）与角落触发范围（24–120dp）都能在设置里实时调整，并在屏幕上给出同源预览；
  放大时**图标最多到 105% 的大小**（再往上只扩大范围），缩小不受限制。
- **窗外关闭**：小窗关闭方式可选 —— 不执行 / 双击小横条（默认）/ 单击空白处 / 双击空白处。
- **上滑迷你窗**：上滑普通小窗底部横条即切换为迷你小窗（不要求「快速」上滑）。
- **应用管理**：最多固定六个外圈 + 五个内圈应用，支持拖动排序，通过“更多”访问其他应用与系统工具。
- **手势设置**：左右入口独立开关，触发热区形状可选扇形 / 三角形。
- **自动暂停**：默认在横屏或游戏模式下暂停增强，退出后自动恢复，可分别关闭。
- **改设置即时生效**：不需要重启手机；关闭模块也能立即让已注入的进程失效。
- **开发模式**：默认关闭，日志只保留关键事件；排障时打开即可看到轮盘几何、面板几何等全套诊断输出。

*更多功能持续开发中。*

## 三改（本仓库）的改动

在二改版本基础上继续修改，修改日期 **2026-10-16 ~ 2026-10-17**，修改者 **2237742261**。
包名改为 `com.eta.flymefreeform`（可与上游、二改版本共存）；所有厂商接口均从设备上的实际 APK / JAR 核对取得，未凭推测。

### 功能

- **上滑手柄 → 迷你小窗**：把普通小窗底部手柄的上滑模式重映射为原生 MINI 模式。原生要求
  `|yVel| ≥ 屏高×0.3` 或位移超过 100dp，慢速上滑会被判成无效手势，这里一并放宽。
- **非迷你态双击底部横条关闭**：原生只在迷你态响应双击，现在普通小窗双击小横条也能关窗；
  另补了「输入法在场」的兜底 —— 第一击被键盘收起吃掉时，仍能靠原始 `dispatchTouchEvent` 认出双击。
- **「小窗关闭方式」四选一**：不执行 / 双击小横条（默认）/ 单击空白处 / 双击空白处。
- **角落轮盘不再被输入法遮挡**：轮盘窗口层级提升到 `TYPE_INPUT_METHOD_DIALOG`，
  键盘弹起时轮盘照样贴在屏幕角上（此前被 `TYPE_APPLICATION_OVERLAY` 与输入法之间的层级关系压住）。
- **轮盘缩放（70%–115%）运行时可调**：拖滑条时设置页角落会画出**与呼出效果同源**的虚线预览，
  松手后不重启直接呼出即为新尺寸。
- **配置推送通道重做**：模块 App 与已注入进程之间改用**签名级权限的导出广播**，
  改任何设置都即时生效；同时提供「关闭模块立即失效」的硬停通道，不必重启手机。
- **开发模式**（默认关）：诊断日志总开关。关着时日志只留关键事件（Hook 安装、模块状态、配置应用、错误），
  打开后轮盘几何、面板几何、图标度量、每次手势与工具调用的诊断行全部回来。

### 修复

- **改设置不生效、必须重启手机**：旧的 `RemotePreferences` 跨进程通知不会回调，改用自建广播通道后解决。
- **停用模块后角落热区仍然活着**：模块停用不会卸载已注入的代码，现由硬停广播让已注入进程自我失效。
- **设置页抖动**：每次写盘都会让整页控件瞬间变灰再恢复，已去掉这层状态。
- **轮盘「改了尺寸看不出变化」**：窗口 `fitScale` 收口会吃掉尺寸差异，另有「每基准 dp = 2.7px」的换算口径，现已按渲染半径核对。

### 更新日志

- **0.2.13**：轮盘缩放超过 **105%** 时图标不再继续变大（滑条只扩大半径与整体范围）；设置页预览同步。
- **0.2.12**：新增「开发模式」开关（默认关）；诊断类日志降级，默认只输出关键事件。
- **0.2.11**：拖「轮盘缩放」滑条时的角落预览改为与「角落触发范围」同款扇形。
- **0.2.10**：设置页瘦身（去掉常驻信息块与多余箭头）；滑条文案改为「即生效」。
- **0.2.9**：轮盘几何定稿（基准半径 250dp / 图标 47.5dp）；输入法弹出时轮盘不再被遮挡。
- **0.2.7**：配置推送通道重做（签名级权限）—— 改设置即时生效、关模块立即失效。
- **0.2.6**：上滑手柄切换迷你小窗；双击底部横条关闭；「小窗关闭方式」可选。

## 二改（Sillybomo）的改动

基于上游 `dbbf0d5`（2026-09-10），修改日期 **2026-09-20**，修改者 **bomo**。
所有厂商接口均从设备上的实际 APK / JAR 核对取得，未凭推测；**ColorOS 16 的适配路径保持原样**。

### 适配

- **ColorOS 17 / Android 17（SDK 37）支持**：重新定位四类已失效的系统 Hook ——
  角落输入入口（`OplusBaseTouchInteractionService`）、SystemUI 应用类
  （`application.impl.SystemUIApplicationImpl`）、输入法窗口字段
  （`DisplayContent.mImeWindow`）、指针抢占通道（`InputMonitorCompat` 已被移除）；
  智能侧边栏版本白名单扩充至 `17.9.2 / 170009002`。
  在此之前，模块在 ColorOS 17 上部分 Hook 装载失败，扇形菜单与「全部」面板均不可用。
- **侧边栏版本判断分级化**：「全部」面板不再要求侧边栏版本号完全一致，
  小版本更新（如 `17.9.2` → `17.9.3`）后仍可继续使用；
  真正不兼容时会在反射阶段安全降级并打印诊断码，不会崩溃。

### 修复

- **扇形菜单图标偏小、方形图标在圆形容器里视觉上变「菱形」**：
  上游对非自适应图标是原样放行的，而 ColorOS 返回的图标位图自身带约 7% 的透明安全区留白，
  放进圆形容器后四周露白。现改为裁掉留白并等比放大填满外框。
- **「全部」面板左上角「关闭」按钮点击无反应**：ColorOS 17 将该按钮的资源 id
  由 `close` 改为 `cancel`，旧 id 查找必然落空，点击被系统原厂逻辑接管。
  现按新 id 重新绑定，面板可正常关闭。

### 优化

- **「全部」面板玻璃观感 1:1 还原原生**：不再使用通用窗口模糊，改为复用系统自带的
  `SidebarPlatformBlurHelper`（posteffect 背景模糊 + AGSL 双层混合 + 材质光照），
  与原厂面板通透度、磨砂感一致；失败时自动回退窗口模糊。
- **扇形几何收紧**：在 7 条目 / 84° 弧 / 槽位间隔 12° 的硬约束下，
  容器半径 −2.5%、图标直径 +8%，把图标尺寸推到上限的 96%（再大需允许图标互叠）。

## 设计与实现

本项目借鉴 Flyme 的快捷交互，复刻扇形菜单的展开动画与滑选体验；“更多”窗口复用 ColorOS 智能侧边栏的“全部”面板，应用窗口继续由系统已有的自由窗能力管理。

完整照搬另一套系统的界面，容易造成视觉与操作上的割裂；另建一套小窗能力，也会增加系统适配与后续维护的成本。因此，我们保留 Flyme 的交互巧思，同时沿用 ColorOS 的界面与窗口能力，让这份体验自然融入当前系统。

## 安装

- 环境：ColorOS（Android 15+，`minSdk 35`）+ LSPosed（libxposed API 102；LSPosed 2.2.1 实测）。
- 作用域：`system`、`systemui`、`launcher`、`com.coloros.smartsidebar`。缺格子会让部分功能不可用，设置页会提示补全。
- 步骤：安装 [Releases](https://github.com/2237742261/FlymeFreeform/releases) 里的 APK →
  在 LSPosed 里启用模块并勾选上述作用域 → **重启手机**。
- 注意：模块的注入点在 system_server（小窗手势、角落轮盘），因此**首次安装或代码更新后需要重启手机**才换用新 dex；
  之后改设置走配置推送通道，即时生效。

## 构建

```bash
./gradlew assembleRelease   # 需要 Android SDK（compileSdk 36）与 JDK 17+
```

`release` 走 R8（含混淆与裁剪）。`app/proguard-rules.pro` 里保留了模块入口类 ——
删掉那条 `-keep` 会让 LSPosed 找不到入口，表现为「装完重启后所有功能失效」。
签名使用仓库根的 `release.keystore`（**不随源码分发**，自行构建请换用自己的密钥）。
